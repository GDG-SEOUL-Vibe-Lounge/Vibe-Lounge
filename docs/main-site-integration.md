# DevFest Seoul 2026 메인 사이트 연동

- 메인 사이트: https://devfest-seoul-2026.vercel.app (소스 저장소: `GDG-Seoul/devfest-2026-seoul`)
- 이 저장소: 쉬는 시간 프로그램 (바이브 라운지, 복도)

> 이 문서는 **배포된 메인 사이트의 공개 코드**(HTML, `app.css`, `app.js`)를 읽고 맞춘 내용이에요.
> 메인 사이트 저장소와 서버 코드(`/api/*`)는 접근 권한이 없어 직접 보지 못했어요. 서버 쪽 가정은 따로 표시했어요.

## 2. 메인 사이트에서 확인한 구조

- 정적 HTML + `/app.js`(ES module) + `/content.js` + 서버리스 `/api/*`
- 티켓 인증: `/?login` (티켓 구매 이메일 + 휴대폰 번호 뒤 4자리) → 닉네임 정하기 → 스탬프판
- 스탬프판: `GET /api/stamp` → `{ nick, qr, count, goal, stamps: [{ id, title, sub, where, art, at, ... }], needs, gacha, blanket }`, 인증 전에는 401
- 도장 지급: 참가자의 "내 QR"(`/staff?u=<qr>` 링크)을 스태프가 스캔해서 지급. 안내 문구에 지급 장소로 **바이브 라운지, 이벤트 부스**가 이미 들어 있음
- 화면 구성: `.topbar`(파란 바), 키 비주얼, `nav.quick`(스탬프, 세션, 궁금해요, 오시는 길), `.section` + `.card`

## 3. 연동 방식 3가지

### A. 다른 도메인 + 서로 링크 (지금 바로 가능, 이번 행사 추천)

- 프로그램은 GitHub Pages에 두고, 메인 사이트에는 섹션 1개와 메뉴 1줄만 추가 ([`main-site-snippet.html`](main-site-snippet.html))
- 참가자는 프로그램에서 닉네임을 한 번 입력
- 참가자가 쓴 글(사연, 아이디어, 댓글)이 메인 사이트와 분리된 도메인에서만 표시되어 가장 안전

### B. 같은 도메인 `/vibe/` 로 올리기

- 방법 1: 메인 저장소에 이 저장소의 정적 파일을 `vibe/` 폴더로 넣기
- 방법 2: 이 저장소를 별도 Vercel 프로젝트로 배포하고 메인 `vercel.json`에 rewrite 추가
  ```json
  { "rewrites": [{ "source": "/vibe/:path*", "destination": "https://<프로그램-프로젝트>.vercel.app/:path*" }] }
  ```
- 효과: 티켓 인증을 마친 참가자는 **닉네임 입력 없이 바로 참여**. 프로그램은 `GET /api/stamp` 응답의 `nick`, `qr` 두 값만 읽고, QR 토큰은 저장하지 않으며 SHA-256 해시 일부만 참가자 구분값으로 사용
- 메인 사이트 담당자가 판단해야 할 점
  - 참가자가 쓴 글을 보여 주는 페이지가 메인 사이트와 **같은 출처**에서 실행됨. 이쪽 페이지에 스크립트 삽입 취약점이 생기면 메인 사이트 로그인 세션까지 영향을 받음. 공유 데이터는 전부 정규화하고 이스케이프해서 표시하며 악성 데이터 테스트를 통과했지만, 같은 출처로 올리기 전에 코드 리뷰를 권장
  - `qr` 값이 참가자별 고정값이라는 가정 (값이 바뀌더라도 같은 기기, 같은 닉네임이면 기존 구분값을 유지하도록 처리해 둠)
  - 인증 후 원래 보던 프로그램으로 돌아오는 기능이 메인 사이트에 없음 (`/?login&next=/vibe/...` 같은 지원이 있으면 매끄러움)
- 검증 범위: 메인 페이지 사본과 `/api/stamp` **모의 응답**으로만 확인함 (인증 전, 인증 후, 닉네임 변경). 실제 서버와 연결한 확인은 못 함

### C. 도장 자동 지급

- 현재 구조에서는 불가. 도장은 스태프 스캔으로만 찍히고, 프로그램이 직접 찍게 하면 누구나 위조할 수 있음
- 필요한 것: 메인 서버에 검증 API 추가 (프로그램 완료 기록을 서버가 확인한 뒤 도장 지급)
- 이번 행사는 A(또는 B) + 스태프 스캔으로 운영하고, C는 다음 행사 과제로 권장

## 4. 메인 사이트 쪽 작업 목록

| 작업 | 필수 여부 | 내용 |
|---|---|---|
| 프로그램 섹션, 메뉴 추가 | A, B 공통 | [`main-site-snippet.html`](main-site-snippet.html)을 스탬프 섹션 아래에 붙이고 `BASE`를 프로그램 주소로 교체. 메인 페이지 사본에 넣어 화면 확인함 |
| 스태프 안내 | 권장 | 프로그램의 완료 인증 화면을 확인한 뒤 QR을 스캔해 도장을 주는 흐름 공유 |
| 행사장 안내도 | 선택 | 바이브 라운지, 복도 프로그램 위치 표시 |
| `/vibe/` 배포와 리뷰 | B안일 때 | 3장 B안 참고 |
